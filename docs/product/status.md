# Fable Status

Last audited: 2026-07-24.

This is the factual state of the repo, not the product pitch. Claims below were checked against current files in this checkout.

> **Document boundary:** [Product Blueprint](vision.md) defines the approved final state. [Master Build Plan](master-build-plan.md) is the ordered execution tracker. This file reports current implementation facts only.

> **Approved workspace direction:** Fable requires a Clerk-backed account, but Clerk supplies identity/session only. Fable owns internal users, workspaces, memberships, and authorization. One workspace model supports one or many members; there is no separate Personal Home, Team Workspace type, Fable Organization layer, or Clerk Organization tenancy. The implementation remains configuration-gated until live Clerk and Convex validation is performed.

## Repo Shape

- The repo is a private pnpm monorepo named `fable`, with apps `@fable/desktop`, `@fable/broker`, `@fable/marketing`, and `@fable/waitlist`, plus packages `@fable/connectors`, `@fable/knowledge`, and `@fable/protocol`.
- The desktop app is Tauri 2 plus React, TypeScript, and Vite.
- The Rust runtime is under `apps/desktop/src-tauri`.
- Product docs already exist for thesis, roadmap, architecture, connectors, native-runtime, release notes, and threat model.
- Brand assets exist under `apps/desktop/public/brand`.

completion receipts, including immutable references, hashes, plan order, and
failed-source truth. Those provider-generated outputs are labelled untrusted and
cannot add policy, approval, or instruction authority; the native provider
request must match the reconstructed objective exactly. Reopen links the durable
progress receipt by Run id, and startup recovery re-derives the same objective
for eligible interrupted workers. Ordinary bullets infer no dependency, and the
command does not infer additional graph edges, tools, consequential effects,
grants, or artifact handoff.

Every declared task requires identified-human review. A new optional Plan
criterion contract binds that review to the exact durable outputs of the Plan
steps that name it. Rust derives those references from encrypted worker or
aggregation facts only after settlement, refuses a passing decision when a
bound output is missing, persists the references in the evaluation, and verifies
them during exact replay. Browser preview exposes only the command affordance;
it does not simulate native Mission execution. Arbitrary multi-stage or branching
dependency graphs, quorum composition, general artifact materialization, dynamic
tool/grant composition, and packaged/live-provider validation remain open.
