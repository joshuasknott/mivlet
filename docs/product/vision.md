# Product direction

Fable is a minimalist, vendor-neutral workspace where a person gives named
agents outcomes in ordinary language. Fable supplies context, selects only from
the providers and capabilities the user has authorized, pauses at consequential
boundaries, and returns inspectable work.

This is direction, not a current-capability checklist. The root `README.md` is
the concise source of truth for repository maturity.

## Experience

The normal loop is intentionally small:

1. Choose or create an agent.
2. Describe the outcome.
3. Review the agent's progress, sources, proposed actions, and approvals.
4. Receive durable results and refine them in conversation.

Projects, knowledge, connections, routines, computers, provider routing, and
advanced orchestration are contextual depth. They should not become permanent
top-level clutter or prerequisites for ordinary work.

## Capability direction

- Provider-neutral model selection through Fable-owned contracts.
- Durable agent identity, responsibilities, context, and inspectable work.
- Local execution for private interactive work and eligible isolated hosted
  computers for explicitly authorized background work.
- Reusable routines expressed as outcomes, with exact-program scheduling kept as
  an advanced tool.
- Browser, filesystem, process, connector, and knowledge capabilities that are
  narrow, observable, and approval-bound.
- One workspace authorization model that can support one or many members without
  delegating Fable tenancy to an identity vendor.

Grok Bot is a capability benchmark, not a brand or implementation source. Fable
must not copy proprietary names, visuals, code, or wording, and it must not claim
parity without measured live evidence.

## Trust model

- Credentials remain behind native or deployment-secret boundaries.
- External content and tool output are untrusted input.
- Consequential actions bind the exact service, action, scope, data preview,
  freshness, and one-time authority immediately before execution.
- Hosted capabilities are workspace-, user-, agent-, device-, generation-, and
  request-fenced.
- Fixtures, simulations, tests, and dry-runs are labeled as such.
- Users can inspect provenance, stop work, change authority, and remove retained
  knowledge or memory.

## Product qualities

Fable should feel calm, direct, and capable. Prefer progressive disclosure,
plain language, strong defaults, compact accessible controls, and honest failure
states. Adding infrastructure must make the conversation simpler rather than
turning the user into an orchestration administrator.

## Current boundary

The repository has a capable local desktop foundation and a deployment-gated
hosted computer/routine foundation. Production hosted operation, secure hosted
sign-in, ordinary-chat continuation, monitoring, metering, mobile control, and
multi-platform release remain incomplete until implemented and live-validated.
